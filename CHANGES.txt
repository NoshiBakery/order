Noshi Bakery — Speed + Security + Drag & Drop v2
=================================================

1) LIVE DATA PERFORMANCE
- No stale cache was added.
- db.js now supports one live batch request for multiple cloud keys through GET /api/data?keys=...
- Pages that need several keys now fetch them in one authenticated HTTP request instead of 2–3 separate requests.
- exportAll now fetches all cloud keys in one live batch request instead of status + sequential requests.
- Worker no longer runs ensureBootstrapUsers() on every API request; bootstrap is only checked during login.
- Incoming website orders changed from an N+1 query pattern (up to 201 D1 queries for 200 orders) to one JOIN query.
- Client page no longer writes the clients array back to D1 every time the page is opened; it writes only when an old record actually needs repair.
- Removed the redundant mandoubOrders write path from new order approval. The active app already reads delivery/mandoub data from salesData, so this removes a duplicate large cloud write and avoids partial-save inconsistencies.

2) DELIVERY SPLIT UI
- Rebuilt the split-delivery planner.
- Drag & Drop only: removed the tap-then-select behavior.
- Every quantity unit is displayed as a real product card with product image + name + unit number.
- Desktop uses native drag/drop.
- iPhone/iPad/Android use a Pointer Events drag implementation with a floating drag ghost and highlighted drop target.
- Clean responsive layout: three product cards per row on small phones, simple schedule cards, clear date/mandoub/delivery-fee controls.
- Every unit must exist exactly once across schedules before saving.
- Existing split orders remain backward-compatible.

3) DATA ACCURACY / EXTERNAL ORDERS
- Dashboard no longer marks a website order as accepted before the internal order is actually saved.
- External order is marked accepted only after salesData is successfully saved.
- externalRequestId duplicate protection prevents a retry from creating a second internal order.
- Removed the duplicate mandoubOrders write to reduce the chance of one cloud key saving while another fails.
- Worker decision update verifies exactly one row was changed, preventing concurrent accept/reject races from being reported as successful.

4) SECURITY
- Worker rejects browser requests that contain an unapproved Origin instead of relying on CORS response hiding alone (CSRF hardening).
- Added API response security headers: X-Frame-Options, CSP frame-ancestors/default-src none, Permissions-Policy, nosniff, no-referrer, no-store.
- Login input length limits added.
- Old login-attempt rows are cleaned automatically.
- 429 responses include Retry-After.
- Frontend auth uses Headers safely and explicitly requests no-store.
- Fixed TOO_MANY_ATTEMPTS message handling on login page.
- Escaped customer/note text in the delivery-products view where public website notes can reach the internal UI.

5) IMAGES / LOAD TIME
- Added 420px WebP thumbnails for the product interface.
- Product thumbnail payload reduced from about 1.89 MB to about 467 KB (~75% smaller).
- Added optimized images/Noshi.webp logo: about 20.8 KB instead of 665 KB (~97% smaller).
- Fixed all internal logo paths to point to the existing images folder.
- Original full-size images are kept untouched for safety/backward compatibility.

6) D1 INDEXES
- cloudflare/noshi-internal-performance.sql: safe idempotent indexes for sessions, login attempts, app data chunks.
- cloudflare/noshi-orders-performance.sql: safe idempotent indexes for new-order listing and order_items lookup.

IMPORTANT DEPLOY ORDER
1. Deploy internal-worker.js FIRST.
2. Then upload the changed GitHub files.
3. SQL index files are safe to run before or after; they do not delete/modify business data.

No D1 data migration or JSON re-import is required for this update.
