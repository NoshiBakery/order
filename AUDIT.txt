Noshi code audit — main findings addressed
==========================================

HIGH IMPACT
- Incoming orders endpoint had an N+1 database query pattern.
  Fixed: one CTE + LEFT JOIN query.

- Worker executed two user-existence D1 reads on every single request through ensureBootstrapUsers().
  Fixed: bootstrap check is only performed during login.

- Browser getMany() still made one HTTP request per key.
  Fixed: one live batch API request; no stale cache.

- External order was marked accepted before the internal order was saved.
  Risk: order could disappear from dashboard if navigation/save failed.
  Fixed: acceptance is finalized only after internal salesData save; duplicate externalRequestId protection added.

- New-order approval wrote the same business order to salesData and mandoubOrders separately.
  Risk: larger writes + partial inconsistency if one save succeeds and the second fails.
  Fixed: active mandoub pages already derive from salesData, so the redundant write was removed.

- CORS was configured correctly for response access, but untrusted browser Origins were not actively rejected.
  Risk: cookie-authenticated CSRF requests can execute even when CORS hides the response.
  Fixed: unapproved Origin is rejected before routing.

MEDIUM IMPACT
- Client page wrote clients to cloud on every page load even when nothing changed.
  Fixed: only repairs old malformed client records when needed.

- Login-attempt table could grow forever from old failed attempts.
  Fixed: automatic cleanup of rows older than 24 hours during login.

- Client/product text from cloud/external notes reached innerHTML in some views.
  Fixed the public-note/customer path in client-products and client name table rendering.

- Product images were already WebP but still oversized for small cards (many 600–900px images).
  Fixed: separate 420px UI thumbnails; originals remain intact.

MONTH ISOLATION REVIEW
- Bulk payment candidates are selected strictly from salesData[current YYYY-MM].
- Undo history entries are keyed by monthKey and restored only inside that same month.
- Undo uses stable orderId first, with legacy index fallback only inside the same month.
- Mandoub month view derives month from each delivery slot's deliveryDate.
- Split-delivery slots carry their own deliveryDate, mandoub, deliveryFee, deliveryPaid and delivered state.

LIVE-DATA RULE
- This patch does not display a cached old cloud snapshot.
- Every NoshiDB cloud get/getMany/exportAll request goes to the authenticated Worker/D1.
- Cache-Control: no-store remains on API responses and fetch uses cache:no-store.
- Revision conflicts still stop stale-device overwrites instead of silently replacing newer data.
